# Owned synthetic Electron annotations

## Status and scope

This route opens the package's fictional sample in a new owned Electron child. It does not connect an existing app. The sample has no product agent, live account, or real authentication operation. Fixed operation counters make escaped UI actions observable in tests.

The standalone package includes this route and its isolated verification suite. Current results belong in [VERIFICATION.md](VERIFICATION.md). The [historical host guide](history/host-guides/ELECTRON_ANNOTATION_FEEDBACK.md) retains the original walkthroughs, counts, and review receipts. Those records do not validate new package bytes.

[Issue 1](https://github.com/leoscricca/pi-annotate-electron/issues/1) tracks the transferred synthetic annotation work. Use the [attached guide](DEVELOPMENT_UI_CONNECTION.md) for an explicitly bootstrapped development app. The two routes retain separate target kinds and close authority.

## Prerequisites and isolation

Build this package's sample before Open. Use Node 24.22 or later, local Electron 44.9.3, and Pi Annotate 0.5.2. The host Pi SDK supplies the developer session. The lockfile pins matching SDK packages for local tests only. No browser plugin or global Pi package installation is necessary.

The helper verifies this picker SHA-256 before use:

The helper does not modify the installed picker. The sample and its controls belong to this package. They do not import the former application backend. Package checks preserve the original strict policy and the frozen legacy catalog. The sample adds only its separately verified exact states.

Each launch receives a new private home, profile, temporary directory, and capture directory. The environment excludes inherited provider credentials and personal Pi resources. The bootstrap verifies fixture provenance and Electron's resolved paths before sample startup. It refuses packaged operation, arbitrary paths, and unrelated targets.

A private inherited IPC pipe connects the launcher and runtime. A fresh secret authenticates control messages. The secret stays in trusted Node closures, not renderer APIs, command arguments, or receipts. Annotation opens no TCP listener, CDP endpoint, or inspector. It does not read Chrome tokens, sockets, profiles, or queues.

## Synthetic walkthrough commands

The package adapter adds `annotate_electron` and `/annotate-electron`. Chrome's `/annotate` command remains unchanged.

1. Run `/annotate-electron open`.
2. Confirm the separate foreground prompt.
3. Open the desired safe UI state in the synthetic window.
4. Run `/annotate-electron none` or `/annotate-electron crop`.
5. Select a supported control.
6. Enter the literal note.
7. Select Submit.
8. Run `/annotate-electron close` after the review.

Use `/annotate-electron cancel` to exit the picker without a note. The workspace remains open. Use `/annotate-electron status` for its target state. The tool accepts the actions `open`, `start`, `cancel`, `status`, and `close`. Its `start` action accepts `none` or `crop`.

Pi reload shuts down the annotation adapter and closes its owned synthetic window. It is not a recovery command for a failed capture. Reload belongs before a new Open, not during the walkthrough.

For a keyboard check, focus the target before step 4.

Open requires an interactive confirmation. Routine automated checks stay hidden and never take desktop focus. Foreground approval does not authorize private content, a debug endpoint, or live authentication.

## Supported picker controls

Only reviewed synthetic content states and known button labels are eligible. The fixed catalog covers the workspace, Model menu, and Settings with an empty draft or `Synthetic annotation draft`. Unknown transcript text, static content, labels, media, or structure cause refusal before capture or metadata delivery. Full, Debug, Etch, DOM edits, global prompt text, and generic commands remain unavailable.

The policy hashes the complete eligible DOM content inside developer world 1004. It normalizes the exact synthetic-home path supplied by the verified launcher. It also omits only four fixed plain-color theme gradients from a known button during hover or active state. Each gradient must match the current theme and interaction state.

Ordinary elements, excluded layers, and relevant pseudo-elements share one image/resource paint inventory. Additional paint retains its property and pseudo identity. Document-root paint and SVG xlink references also enter the fingerprint.

Before exclusion, the badge and every plain cursor/selection descendant receive explicit own/pseudo paint checks. Empty text does not establish harmless paint. Unknown media or generated content causes refusal.

Those exceptions do not apply to pseudo-elements, extra layers, image URLs, unknown gradients, or idle buttons. It does not normalize arbitrary filenames, text, labels, or owner paths. No raw DOM leaves that world through the annotation protocol. Sample UI changes require controlled fixture calibration and review, not a baseline from an owner window.

Mouse selection does not invoke the selected product button. Enter or Space selects a focused button while annotation is active. App shortcuts remain suppressed. The note field accepts text without a product operation.

None performs no screenshot operation. Crop uses the per-note camera choices. If every note excludes its image, the helper performs no screenshot operation. Unknown image intent causes refusal rather than an inferred image choice.

Visible authentication challenges, secret inputs, unrelated regions, and unknown editable content cause refusal. Only the known synthetic draft text `Synthetic annotation draft` in the known composer is a permitted nonempty draft fixture. This exception is not a general secret detector. Other draft values remain unsupported. Metadata never contains editable values, full HTML, arbitrary attributes, or unrelated transcript content.

Selectors use structural tag paths and numeric positions. Feedback contains no element IDs or classes.

## Transport and request ownership

The control schema admits only fixed annotation operations. It binds messages to one session, target, request, generation, and secret. Renderer admission requires the exact live main frame and owned window. Paths, evaluation requests, authentication commands, extra fields, and invalid modes cause refusal.

Control messages have a 16 KiB limit. Results have a 16 MiB limit. Metadata permits ten selections, 4,096 characters per comment, and 256 KiB in total. Images have a 10 MiB limit each. The image area limit is 16,777,216 pixels.

One request reserves the target before asynchronous content checks, preparation, or picker activation. Cancellation joins preparation and any late activation before cleanup can settle. The request retains ownership until its actual capture, file operations, and cleanup settle.

A busy target refuses replacement. Cancellation and the default 300-second deadline revoke delivery immediately. They do not prove that operations finished. Unknown cleanup retains its ownership block and evidence.

Open reserves its session slot before the foreground confirmation. A second Open request cannot reserve an occupied session slot. Retirement joins any actual launch and closes only its own handle once. An old refusal cannot delete a newer reservation.

Session switch, fork, tree navigation, and shutdown revoke delivery before cleanup. Cancellation, closure, and target retirement also revoke feedback during image preparation. A failed close blocks new targets. A late result never becomes a successful new message. The adapter has no automatic replay queue.

## Images and retained evidence

Crop needs a transient image of the owned renderer. The broker checks geometry, viewport, scroll, scale, request, and document identity. It validates the picker's image, then saves its own canonical crop from the same frame. The full renderer image never becomes a saved file or delivered image. A capture error cannot produce a successful path.

The private capture directory uses mode `0700`. Verified PNGs use random names and mode `0600`. The capture ledger records files with `pending` or `committed` state. A file committed during cancellation remains evidence, not successful feedback.

After confirmed child closure with exit code zero and no signal or termination request, the launcher removes only its synthetic home, profile, and temporary directory. Captures, ledgers, logs, and receipts persist. Unknown process outcomes keep profile cleanup blocked. Failed profile cleanup retains captures and receipts. A cleanup receipt confirms profile removal.

Capture removal requires a separate owner request for identified owned paths. The evidence helper reports eligibility only. It does not authorize or perform removal. Chrome captures, queues, tokens, and unrelated app sessions remain untouched.

## Restoration and feedback authority

The helper records focus, selection, cursor, scroll, and relevant accessibility state before activation. Cleanup removes only owned overlay effects. It restores recorded values while original nodes still exist. It does not reset unrelated application accessibility changes to assumed defaults. An unconfirmed restoration blocks readiness.

The Pi message labels comments, selectors, labels, styles, and images as untrusted review data. The command sends feedback only to its source Pi session, without template expansion. A tool call returns its result without a duplicate user message. Annotation grants no source-edit, process, authentication, publication, or deployment authority. A separate owner request remains necessary.

## Acceptance boundary

The frozen catalog retains all 25 legacy states and 36 legacy control labels. The controlled sample adds eight exact states and one known theme control. The strict policy and four hover and active paint exceptions remain unchanged. Package checks verify their source identities.

Fresh native checks, zero-capture refusal tests, state restoration, real offline Pi delivery, and independent review remain necessary for the extracted package. Historical owner walkthroughs validate their original bytes only. No existing owner app or historical process forms part of routine tests.

Private sessions, live providers, Windows, signed distribution, deployment, and global installation remain outside this migration. Comments grant no edit authority. The owner approved public MIT distribution; publication status is tracked in the release guide.
