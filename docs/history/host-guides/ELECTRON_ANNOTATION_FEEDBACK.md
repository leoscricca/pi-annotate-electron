## Synthetic walkthrough commands

The project-local adapter adds `annotate_electron` and `/annotate-electron`. Chrome's `/annotate` command remains unchanged.

1. Run `/annotate-electron open`.
2. Confirm the separate foreground prompt.
3. Open the desired safe UI state in the synthetic window.
4. Run `/annotate-electron none` or `/annotate-electron crop`.
5. Select a supported control.
6. Enter the literal note.
7. Select Submit.
8. Run `/annotate-electron close` after the review.

Use `/annotate-electron cancel` to exit the picker without a note. The workspace remains open. Use `/annotate-electron status` for its target state. The tool accepts the actions `open`, `start`, `cancel`, `status`, and `close`. Its `start` action accepts `none` or `crop`.

Pi reload shuts down the annotation adapter and closes its owned synthetic window. It is not a recovery command for a failed capture. Reload belongs before a new Open, not during the walkthrough.

For a keyboard check, focus the target before step 4.

Open requires an interactive confirmation. Routine automated checks stay hidden and never take desktop focus. Foreground approval does not authorize private content, a debug endpoint, or live authentication.

## Supported picker controls

Only reviewed synthetic content states and known button labels are eligible. The fixed catalog covers the workspace, Model menu, and Settings with an empty draft or `Synthetic annotation draft`. Unknown transcript text, static content, labels, media, or structure cause refusal before capture or metadata delivery. Full, Debug, Etch, DOM edits, global prompt text, and generic commands remain unavailable.

The policy hashes the complete eligible DOM content inside developer world 1004. It normalizes the exact synthetic-home path supplied by the verified launcher. It also omits only four fixed plain-color theme gradients from a known button during hover or active state. Each gradient must match the current theme and interaction state.

Ordinary elements, excluded layers, and relevant pseudo-elements share one image/resource paint inventory. Additional paint retains its property and pseudo identity. Document-root paint and SVG xlink references also enter the fingerprint.

Before exclusion, the badge and every plain cursor/selection descendant receive explicit own/pseudo paint checks. Empty text does not establish harmless paint. Unknown media or generated content causes refusal.

Those exceptions do not apply to pseudo-elements, extra layers, image URLs, unknown gradients, or idle buttons. It does not normalize arbitrary filenames, text, labels, or owner paths. No raw DOM leaves that world through the annotation protocol. Product UI changes require controlled fixture calibration and review, not a baseline from an owner window.

Mouse selection does not invoke the selected product button. Enter or Space selects a focused button while annotation is active. App shortcuts remain suppressed. The note field accepts text without a product operation.

None performs no screenshot operation. Crop uses the per-note camera choices. If every note excludes its image, the helper performs no screenshot operation. Unknown image intent causes refusal rather than an inferred image choice.

Visible authentication challenges, secret inputs, unrelated regions, and unknown editable content cause refusal. Only the known synthetic draft text `Synthetic annotation draft` in the known composer is a permitted nonempty draft fixture. This exception is not a general secret detector. Other draft values remain unsupported. Metadata never contains editable values, full HTML, arbitrary attributes, or unrelated transcript content.

Selectors use structural tag paths and numeric positions. Feedback contains no element IDs or classes.

## Transport and request ownership

The control schema admits only fixed annotation operations. It binds messages to one session, target, request, generation, and secret. Renderer admission requires the exact live main frame and owned window. Paths, evaluation requests, authentication commands, extra fields, and invalid modes cause refusal.

Control messages have a 16 KiB limit. Results have a 16 MiB limit. Metadata permits ten selections, 4,096 characters per comment, and 256 KiB in total. Images have a 10 MiB limit each. The image area limit is 16,777,216 pixels.

One request reserves the target before asynchronous content checks, preparation, or picker activation. Cancellation joins preparation and any late activation before cleanup can settle. The request retains ownership until its actual capture, file operations, and cleanup settle.

A busy target refuses replacement. Cancellation and the default 300-second deadline revoke delivery immediately. They do not prove that operations finished. Unknown cleanup retains its ownership block and evidence.

Open reserves its session slot before the foreground confirmation. A second Open request cannot reserve an occupied session slot. Retirement joins any actual launch and closes only its own handle once. An old refusal cannot delete a newer reservation.

Session switch, fork, tree navigation, and shutdown revoke delivery before cleanup. Cancellation, closure, and target retirement also revoke feedback during image preparation. A failed close blocks new targets. A late result never becomes a successful new message. The adapter has no automatic replay queue.
